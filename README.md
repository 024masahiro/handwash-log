# 手洗いログ

職員が本人の手洗い回数を記録し、管理者が利用者別の回数を確認するウェブアプリです。

画面は GitHub Pages、ログイン・記録保存・権限確認は既存の Sites サーバーで実行します。GitHub の公開リポジトリや Pages ファイルに、利用者名簿、手洗い記録、パスワード、送信サービスの秘密鍵を保存しません。

## 利用方法

- 「新規登録」で氏名・メールアドレス・パスワードを入力します。
- メールアドレスとパスワードでログインし、「手を洗った」で本人の記録を保存します。
- 管理者はダッシュボードで日付を選び、利用者別の回数と最終記録を確認できます。
- 本人はアカウント設定から退会できます。管理者は一般利用者を削除できます。退会・削除では、その利用者の記録も削除します。
- 管理者権限は一般の登録画面から取得できません。初期設定は既存サーバーのサイト所有者だけが行えます。
- パスワード再設定メールの自動送信には、既存サーバーの「サイト所有者の設定」で Resend の認証済み送信元と API キーを設定します。再設定リンクは15分で失効し、一度だけ使用できます。

## GitHub Pages の公開

`main` ブランチの更新で `.github/workflows/pages.yml` が実行され、画面を公開します。リポジトリの Settings → Pages → Build and deployment → Source は **GitHub Actions** に設定します。

公開設定は `github-pages.json` です。`api_origin` は記録保存用サーバーのURL、`base_path` はリポジトリ名に対応するパスです。これらは公開情報であり、秘密鍵を入れてはいけません。

```sh
node scripts/build-pages.mjs
```

生成ファイルは `pages-dist/` に出力します。ログイン、新規登録、パスワード再設定、管理画面の各URLにも `index.html` を生成するため、GitHub Pagesで直接リンクを開けます。

## サーバーの運用

サーバーは既存の公開先で継続稼働します。GitHub Pages単体ではログインやデータ保存の処理を実行できません。サーバーを停止すると、GitHub Pagesの画面からも記録できなくなります。

Sites の秘密値には `HANDWASH_ADMIN_EMAIL` と `HANDWASH_SETTINGS_KEY` を設定します。GitHub Pages向けには次の公開設定もサーバーに設定します。

- `HANDWASH_ALLOWED_ORIGIN`: 許可する GitHub Pages のオリジン
- `HANDWASH_FRONTEND_URL`: 公開済みのアプリURL。再設定メールの戻り先として使用

設定例は `.env.example` にあり、実際の秘密値は含みません。GitHub Pagesからの認証はブラウザのタブ内セッションを使用し、第三者Cookieを必要としません。サーバーではセッションのハッシュだけを保存し、本人の記録・管理者専用操作をそれぞれ確認します。

```sh
npm ci
npm run build
npm run check
```

サーバーの更新は Sites、画面の更新は GitHub Pages のワークフローで公開します。サーバーの構造を変更するときは、既存のデータと生成済みのマイグレーションを保持してください。
